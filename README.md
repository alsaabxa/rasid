# منصة راصد متعددة المدارس — النشر على Firebase

تحتفظ هذه النسخة بواجهة رصد الغياب وتقاريرها، وتضيف إنشاء حساب مدرسة بالبريد وكلمة المرور، انتظار اعتماد مالك المنصة، وتخزين بيانات كل مدرسة في مساحة Firestore منفصلة.

## تجهيز Firebase مرة واحدة

1. النسخة مرتبطة بالمشروع الإنتاجي `fir-rc-91dbc` في `firebase-config.js` و`.firebaserc`. حافظ على هذا المعرّف ولا تستبدله بمشروع الاختبار.
2. في المشروع الإنتاجي، تم التحقق من تفعيل **Email/Password** و**Google**، ومن السماح بنطاق `rasid-sa-2026.web.app` ضمن النطاقات المعتمدة.
3. من **Authentication → Users** أنشئ حساب مدير المنصة ببريد `admin.html` وكلمة مرور قوية، ثم أكّد البريد الإلكتروني. يجب أن يكون البريد نفسه في `firestore.rules` و`admin.html`، وأن يكون موثقًا كي تعمل صلاحيات الإدارة.
4. تحقّق أولًا من قاعدة Firestore الحالية وإصدارها وموقعها في المشروع. انشر `firestore.rules` إلى القاعدة المقصودة فقط؛ لا تنشئ قاعدة جديدة أو تغيّر الموقع قبل تأكيد الهدف.
5. جرّب محليًا باستخدام Firebase Hosting Emulator أو انشر الاستضافة.

## مستودع GitHub والنشر التلقائي

المستودع هو `alsaabxa/rasid`. ملف سير العمل هنا مضبوط لاستهداف موقع Hosting `rasid-sa-2026` وقناة الإنتاج `live` في `fir-rc-91dbc` عند التحديث على `main`، باستخدام السر `FIREBASE_SERVICE_ACCOUNT_FIR_RC_91DBC`. يجب رفع هذا التعديل إلى GitHub حتى يسري على النشر التلقائي. هذا السير ينشر Hosting فقط؛ انشر قواعد Firestore منفصلًا عند تعديلها.

## اعتماد المدارس

- تستخدم المدرسة صفحة المنصة لتسجيل اسم المدرسة بالبريد وكلمة المرور (6 أحرف على الأقل)، أو تختار Google من تبويب تسجيل مدرسة جديدة. في الحالتين يلزم اعتماد الطلب قبل الدخول.
- يبقى طلبها بحالة معلّقة ولا تدخل للوحة حتى اعتماده.
- أنت تدخل إلى `/admin.html` بحساب المدير، ثم تضغط **اعتماد**. تستطيع بعدها المدرسة تسجيل الدخول.
- الرفض يمنع دخولها. يمكن للمدير متابعة الطلبات المعلقة في الصفحة نفسها.
- تحفظ بيانات المدرسة تحت `schools/{schoolId}/private` كسجلات منفصلة `v2_*`، ويحتوي `appMeta` على إصدار البنية ورقم المراجعة. تكتب التغييرات على دفعات، وتفحص الأجهزة الأخرى رقم المراجعة كل أربع ثوانٍ ثم تعيد تحميل السجلات عند تغيّره.

## ملاحظات تشغيل

- توزيع السجلات على مستندات متعددة يتجنب وضع حالة المدرسة كلها في مستند واحد، مع بقاء حد حجم Firestore البالغ 1 MiB لكل مستند.
- النسخة الجديدة تبدأ بيانات المدارس الجديدة فارغة. بيانات النسخة القديمة المرتبطة بـ Google Apps Script لا تُنقل تلقائيًا.
- لا تضع Service Account أو مفاتيح إدارية في ملفات الموقع. إعداد Firebase Web الظاهر في `firebase-config.js` مخصص للعميل؛ الأمان الفعلي من قواعد Firestore.
