# منصة راصد متعددة المدارس — النشر على Firebase

تحتفظ هذه النسخة بواجهة رصد الغياب وتقاريرها، وتضيف إنشاء حساب مدرسة بالبريد وكلمة المرور، انتظار اعتماد مالك المنصة، وتخزين بيانات كل مدرسة في مساحة Firestore منفصلة.

## تجهيز Firebase مرة واحدة

1. أنشئ مشروعًا من [Firebase Console](https://console.firebase.google.com/) ثم أضف تطبيق ويب. انسخ إعدادات التطبيق إلى `firebase-config.js`، واستبدل `YOUR_PROJECT_ID` في `.firebaserc` بمعرّف المشروع.
2. من **Authentication → Sign-in method** فعّل **Email/Password** و**Google**. في إعداد Google اختر اسم الدعم والبريد، واحفظ التغييرات. أضف نطاق Firebase Hosting (وأي نطاق مخصص) إلى **Authentication → Settings → Authorized domains**.
3. من **Authentication → Users** أنشئ حسابًا لك ببريد مدير المنصة وكلمة مرور قوية. استخدم البريد نفسه في `OWNER_EMAIL_CHANGE_ME` داخل `firestore.rules` و`admin.html`.
4. أنشئ قاعدة **Firestore Database** في وضع الإنتاج، ثم انشر `firestore.rules` (تلقائيًا إذا استخدمت Firebase CLI، أو الصق محتواها في تبويب Rules).
5. جرّب محليًا باستخدام Firebase Hosting Emulator أو انشر الاستضافة.

## ربط GitHub والنشر التلقائي

1. ارفع محتويات هذا المجلد إلى مستودع GitHub جديد، مع التأكد من تحديث `firebase-config.js` و`.firebaserc` وبريد المدير في الملفين المذكورين.
2. في Firebase Console افتح **Hosting → Get started → Set up GitHub Action**، وصّل حساب GitHub واختر المستودع والفرع الرئيسي.
3. اختر مجلد النشر `.` (جذر المشروع) ووافق على إنشاء سير عمل GitHub Actions. ستضيف Firebase بيانات اعتماد النشر إلى GitHub تلقائيًا.
4. من **Hosting → Deploys** راقب أول نشر. بعد ذلك كل `push` إلى الفرع المتصل ينشر النسخة تلقائيًا.
5. افتح رابط Firebase Hosting، سجّل طلب مدرسة تجريبية، ثم افتح `https://رابط-موقعك/admin.html` وسجّل ببريد المدير لاعتمادها أو رفضها.

## اعتماد المدارس

- تستخدم المدرسة صفحة المنصة لتسجيل اسم المدرسة بالبريد وكلمة المرور (6 أحرف على الأقل)، أو تختار Google من تبويب تسجيل مدرسة جديدة. في الحالتين يلزم اعتماد الطلب قبل الدخول.
- يبقى طلبها بحالة معلّقة ولا تدخل للوحة حتى اعتماده.
- أنت تدخل إلى `/admin.html` بحساب المدير، ثم تضغط **اعتماد**. تستطيع بعدها المدرسة تسجيل الدخول.
- الرفض يمنع دخولها. يمكن للمدير متابعة الطلبات المعلقة في الصفحة نفسها.
- بيانات التطبيق تحفظ تحت `schools/{schoolId}/private/appData`، وقواعد Firestore تقصر القراءة والكتابة على حسابات المدرسة المعتمدة.

## ملاحظات تشغيل

- هذا التطبيق يستخدم مستند Firestore واحدًا لحالة كل مدرسة؛ Firestore يفرض حدًا لحجم المستند (1 MiB). يلزم تقسيم السجلات إلى مستندات متعددة قبل توسع كبير أو تاريخ حضور طويل.
- النسخة الجديدة تبدأ بيانات المدارس الجديدة فارغة. بيانات النسخة القديمة المرتبطة بـ Google Apps Script لا تُنقل تلقائيًا.
- لا تضع Service Account أو مفاتيح إدارية في ملفات الموقع. إعداد Firebase Web الظاهر في `firebase-config.js` مخصص للعميل؛ الأمان الفعلي من قواعد Firestore.
